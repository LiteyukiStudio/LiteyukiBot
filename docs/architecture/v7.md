# LiteyukiBot v7 Alpha15 Architecture

## Release Boundary

Alpha15 is a CPython 3.14 application with four lockstep distributions, all
version `7.0.0a15`:

| Distribution | Owner |
| --- | --- |
| `liteyukibot-v7` | CLI, configuration, application composition, and built-in features. |
| `liteyukibot-v7-kernel` | JSON-safe events/actions, EventBus, services, lifecycle, and status contracts. |
| `liteyukibot-v7-cordis` | Trusted in-process scopes and ordered handlers. |
| `liteyukibot-v7-adapter-onebot` | OneBot v11 SnowLuma WebSocket transport and conversion. |

The workspace and signed release bundle contain only these distributions.
Satori, NoneBot, generic runtime bridges, standalone Broker/LYIP, WebUI,
Agent, LYF, and native IPC are retired from the Alpha15 support surface.
Snapshots under `extras/legacy-bridges/` are historical source material, not
workspace members or dependency targets.

## Runtime Composition

The root application loads immutable configuration schema 7, creates the
kernel EventBus and action service, activates the built-in feature catalog, and
then starts configured OneBot v11 accounts. Built-in permissions, commands,
resources, profile, and essentials are ordinary root-owned Cordis features;
they are not separately installed plugin distributions.

OneBot accounts translate supported private/group message events into kernel
`EventEnvelope` values. Actions are source-bound and are sent through the
originating account. Connection loss fails pending calls and discards reply
routes. The adapter owns WebSocket connections, authentication, conversion,
and OneBot-specific API details; kernel code sees only portable contracts.

Cordis is trusted Python in the application process. `Scope` provides lazy
dependencies, owned cleanup, and deterministic ordered handlers. It is not a
malicious-code sandbox and does not transfer framework SDK objects across the
kernel boundary.

## Configuration

`config_version = 7` is required. The active sections are `core`, `logging`,
`i18n`, `cordis`, `permissions`, `commands`, `resources`, `profile`,
`essentials`, and `onebot`. Broker, daemon, HTTP, WebUI, runtime, agent, and
vault sections are rejected as removed Alpha15 configuration.

## Contracts And Validation

The kernel package owns the public event, action, service, lifecycle, and
status contracts. Cordis and OneBot depend on exact kernel version pins. The
release registry, bundle manifest, isolated install verifiers, and CI are the
authoritative release checks. The complete local sequence is:

```bash
uv sync --locked --all-packages
uv run liteyuki check
uv run ruff check src tests scripts examples packages
uv run mypy
uv run pytest
uv build --all-packages --out-dir dist/workspace --clear
```

Run the kernel, Cordis, and OneBot isolated verifiers after building. The root
tool smoke test verifies the installed CLI separately.

## External OneBot Project

The adapter is independently written and does not bundle SnowLuma source,
native addons, or assets. SnowLuma is external; LiteyukiBot makes no claim of
affiliation or endorsement. Operators must follow the external project's terms
and handle service, privacy, and platform risks. See the
[adapter notice](../../packages/adapter-onebot/README.md) and the
[SnowLuma project](https://github.com/SnowLuma/SnowLuma).
